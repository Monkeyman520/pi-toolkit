## Requirements

1. **Private Bun workspace and unified toolchain:** Establish a private repository-root Bun workspace (`package.json` with `"private": true`, `"license": "MIT"`, `"type": "module"`, `"workspaces": ["packages/*"]`, and a single root `bun.lock`), a repository root `LICENSE` (MIT), a repository root `CHANGELOG.md` (using Pi-compatible semver headings such as `## [X.Y.Z]` or `## X.Y.Z - YYYY-MM-DD`), a shared root `biome.json`, and a shared `tsconfig.base.json` extended by root scripts/tests (`tsconfig.json`) and each package. Provide root orchestration scripts (`check`, `check:fix`, `format`, `typecheck`, `build`, `test`) that execute workspace package commands sequentially in their package working directories rather than relying on bare root `bun test`. Remove superseded package-local `package-lock.json` files and duplicate per-package Biome configs while preserving independent per-package installation boundaries under `packages/<plugin-name>/` ([ADR 0001](../adr/0001-independently-installable-pi-packages.md)).
2. **Per-package Rolldown ESM bundling:** Configure Rolldown (`rolldown.config.mjs`) for every plugin package (`pi-auto-resume`, `pi-pretty-session`, `pi-quota-keeper`, `pi-session-tree-explorer`, `pi-prompt-pipeline`, and `pi-context-aco`) to bundle its extension entry into `dist/index.js` (ESM with sourcemap, clean output directory), emit `dist/LICENSE` copied from the repository root `LICENSE`, and emit `dist/CHANGELOG.md` copied from the repository root `CHANGELOG.md`. Update each plugin manifest's `pi` field to `{ "extensions": ["./dist/index.js"], "changelogPath": "./dist/CHANGELOG.md" }` and add `build` and `prepack` scripts (`"prepack": "bun run build"`), keeping local source-dev scripts (e.g., `dev`) where helpful. Keep `node:*` built-ins, host-provided peers (`@earendil-works/*`, `typebox`), and declared third-party runtime dependencies (`proper-lockfile` in `pi-quota-keeper`) external so they are never bundled into `dist/index.js`.
3. **Internalized private support library:** Keep `packages/pi-plugin-support` permanently `"private": true` and excluded from npm publication. Resolve `pi-plugin-support` via Bun workspace dependencies at development/build time and inline its imported modules into each consuming plugin's `dist/index.js` during Rolldown bundling. Remove `packages/*/vendor/pi-plugin-support-*.tgz`, npm `bundledDependencies` / `bundleDependencies`, and `scripts/package-support.mjs`. Preserve [ADR 0005](../adr/0005-versioned-plugin-support-library.md) invariants: each loaded plugin owns its own instances and lifecycles with no shared mutable runtime manager, and cross-plugin settings-panel discovery continues to interoperate over `pi.events` across independently bundled plugins.
4. **Migration to `bun test` and updated runtime verification:** Migrate all unit and integration tests across all seven packages and root tests from Vitest to `bun:test`, removing `vitest` from manifests and lockfiles and replacing Vitest-specific APIs (`vi.fn`, `vi.spyOn`, `vi.useFakeTimers`, `vi.stubEnv`, `vi.hoisted`, `vi.mock`) with `bun:test` equivalents without regressing test coverage. Update repository-level and package-level Pi loading/isolation verification (`tests/plugin-isolation.mjs`, `tests/support-library-smoke.mjs` if retained/adapted, and `packages/*/tests/*smoke*`) so packed tarballs are verified against built `dist/index.js` entries, `dist/CHANGELOG.md` readability, and absence of `vendor/*.tgz` / bundled host SDKs.
5. **Public npm package metadata, native Pi update contract, and configurable release catalog:**
   - Configure the five initially published plugin packages as public scoped packages under `@monkeyman520/*`:
     - `@monkeyman520/pi-auto-resume` (`packages/pi-auto-resume`)
     - `@monkeyman520/pi-pretty-session` (`packages/pi-pretty-session`)
     - `@monkeyman520/pi-quota-keeper` (`packages/pi-quota-keeper`)
     - `@monkeyman520/pi-session-tree-explorer` (`packages/pi-session-tree-explorer`)
     - `@monkeyman520/pi-prompt-pipeline` (`packages/pi-prompt-pipeline`)
   - Each public package manifest must omit `"private": true` and declare `"license": "MIT"`, `"publishConfig": { "access": "public" }`, `"keywords": ["pi-package"]`, `"engines": { "node": ">=22.19.0" }`, `"repository": { "type": "git", "url": "git+https://github.com/Monkeyman520/pi-toolkit.git", "directory": "packages/<pkg-name>" }`, explicit `files` allowlist (including `dist`, `README.md`, and package-specific shipped assets such as `examples` for `pi-prompt-pipeline`), and `"pi": { "extensions": ["./dist/index.js"], "changelogPath": "./dist/CHANGELOG.md" }`.
   - Satisfy Pi's native update detection and post-update changelog display (`pi update --extensions`, `pi update npm:@monkeyman520/<pkg>`, `pi -e npm:@monkeyman520/<pkg>`, and Pi's startup **"Extension Updates"** notice) strictly through npm `latest` dist-tag publication and bundled `dist/CHANGELOG.md`, without adding runtime outbound network polling inside extensions.
   - Keep `packages/pi-context-aco` as `"private": true` and excluded from the initial public release list while experimental, with the release script's publishable package list structured as a single explicit configuration entry so `pi-context-aco` can be opted in later without redesigning the release pipeline.
   - Keep the workspace root and `packages/pi-plugin-support` `"private": true` and excluded from release publication.
6. **Release automation script (`scripts/release.ts`):** Provide a Node-executable TypeScript release helper supporting `validate`, `pack`, `verify`, and `publish` modes for `Monkeyman520/pi-toolkit`:
   - **Tag, changelog, & manifest validation (`validate`):** Accept only stable `vX.Y.Z` tags (rejecting prerelease, malformed, or non-safe-integer versions). Verify the workspace root is `private: true`, repository root `CHANGELOG.md` exists and contains a Pi-compatible heading matching `X.Y.Z` (e.g., `## [X.Y.Z]` or `## X.Y.Z` with optional date/suffix), and every configured public package has exact name `@monkeyman520/<dir>`, exact version `X.Y.Z`, `private !== true`, `publishConfig.access === "public"`, `keywords` containing `"pi-package"`, matching `repository.url` and `repository.directory`, safe `files` entries including `dist`, `pi.extensions` equal to `["./dist/index.js"]`, and `pi.changelogPath` equal to `"./dist/CHANGELOG.md"`. Never auto-bump versions, edit changelogs, create commits, or modify tags.
   - **Tarball packing & verification (`pack`, `verify`):** Pack each configured public package into `dist/release/` using `npm pack --json --ignore-scripts --pack-destination` (reusing already-built artifacts without rebuilding). Verify `dist/release/` contains exactly the expected versioned tarballs (`monkeyman520-<dir>-<version>.tgz`) and verify each tarball has no unsafe paths, symlinks, duplicate members, `node_modules`, or `.env`; contains only allowed files; includes required `package.json`, `dist/index.js` (non-empty), `dist/LICENSE` (byte-identical to root `LICENSE`), `dist/CHANGELOG.md` (byte-identical to root `CHANGELOG.md` and containing the `X.Y.Z` heading), and declared non-`dist` files; and preserves critical manifest fields identically.
   - **Idempotent npm Trusted Publishing, `latest` verification, & GitHub Release delivery (`publish`):** Re-verify tarballs before external calls. For each configured public package, query npm registry for exact version `X.Y.Z` (HTTP 404 means absent; non-OK or mismatched identity aborts). Skip re-uploading exact already-published versions; otherwise run `npm publish <tarball> --access public --tag latest --ignore-scripts --registry https://registry.npmjs.org` (relying on OIDC, never a stored token, and never attempting to publish an invalid semver dist-tag such as `vX.Y.Z`). After upload (and when verifying an already-published version on retry), confirm on npm that **both** exact version `X.Y.Z` is available **and** `dist-tags.latest === X.Y.Z` (polling until confirmed or timeout; fail visibly if `dist-tags.latest` does not point to `X.Y.Z`), guaranteeing `pi update --extensions` detects the release. Only after all configured public packages are confirmed live and tagged `latest` on npm, create or resume one non-prerelease GitHub Release for tag `vX.Y.Z` (starting as draft with `generate_release_notes: true`), upload each `.tgz` asset (skipping matching SHA-256 digests and replacing mismatched same-name assets without duplicates), and finalize the Release with `draft: false`, `prerelease: false`, and `make_latest: "true"` (without pushing a separate movable Git `latest` tag).
7. **GitHub Actions workflows (`ci.yml` and `release.yml`):**
   - **CI workflow (`.github/workflows/ci.yml`):** Trigger on `pull_request` and `push` to `main`. Run on Ubuntu with Node.js >= 22.19.0 and pinned Bun: `bun install --frozen-lockfile`, `bun run check`, `bun run typecheck`, `bun run build`, and `bun run test`.
   - **Release workflow (`.github/workflows/release.yml`):** Trigger only on `push.tags: ['v[0-9]*']`, guarded by `github.repository == 'Monkeyman520/pi-toolkit'`, with per-ref `concurrency` (`cancel-in-progress: false`).
     - `validate` job (`permissions: contents: read`): checkout exact `github.sha` (`persist-credentials: false`), setup Node.js and Bun, validate tag, changelog, and manifests, `bun install --frozen-lockfile`, `bun run check`, `bun run typecheck`, `bun run build`, `bun run test`, pack and verify tarballs, and upload `dist/release/*.tgz` as artifact `release-tarballs` (7-day retention, `if-no-files-found: error`, `overwrite: true`).
     - `publish` job (`needs: validate`, `permissions: contents: write, id-token: write`): checkout exact `github.sha` (`persist-credentials: false`), setup Node.js and OIDC-capable `npm@11`, download `release-tarballs`, and execute `scripts/release.ts publish "$RELEASE_TAG"` with `GITHUB_TOKEN: ${{ github.token }}`. Do not reference `NPM_TOKEN` or `NODE_AUTH_TOKEN`.
8. **Maintainer release documentation and repository docs alignment:**
   - Add `docs/releasing.md` (English) documenting the release contract, one-time npm initial-package bootstrap (staged publishing for new scoped packages), per-package npm Trusted Publishing (OIDC) configuration for `Monkeyman520/pi-toolkit` and `release.yml` (and how to opt in `pi-context-aco` later), updating root `CHANGELOG.md` and aligned manifest versions before tagging, failure recovery and rerun semantics, and the offline evidence boundary.
   - Update `AGENTS.md`, root `README.md`, `packages/README.md`, and package READMEs to accurately reflect the Bun + TypeScript + Biome + Rolldown + `bun test` stack, `@monkeyman520/*` package identities, unpinned installation (`pi install npm:@monkeyman520/<pkg>`) and update commands (`pi update --extensions`, `pi update npm:@monkeyman520/<pkg>`), and verified commands.

## Solution

A private root Bun workspace unifies dependency resolution, Biome formatting/linting, base TypeScript compilation checks, Rolldown bundling, and sequential per-package `bun test` execution across all seven packages under `packages/*`. Each plugin builds independently via Rolldown into `dist/index.js`, `dist/LICENSE`, and `dist/CHANGELOG.md`, inlining the private workspace `pi-plugin-support` library into consumer bundles while keeping Node built-ins, Pi host peers, `typebox`, and declared third-party runtime dependencies (`proper-lockfile`) external.

Automated quality assurance runs on every PR and `main` push via `.github/workflows/ci.yml`. Automated releases run via `.github/workflows/release.yml` and `scripts/release.ts` when a maintainer pushes a prepared stable tag `vX.Y.Z`: a read-only `validate` job verifies version alignment and a matching `X.Y.Z` heading in root `CHANGELOG.md`, runs all checks/builds/tests, and packs/inspects tarballs once; a dependent `publish` job rechecks the downloaded tarballs, publishes missing package versions to npm via OIDC Trusted Publishing using npm 11+ with `--tag latest`, verifies that both exact version `X.Y.Z` and `dist-tags.latest === X.Y.Z` are live on npm (enabling `pi update --extensions` and Pi's startup "Extension Updates" changelog notice), and finalizes one stable GitHub Release (`make_latest: "true"`) with generated notes and the checked `.tgz` assets.

## End-to-End Tests

### Workspace quality gate and built-plugin Pi loading succeed
- **Given:** Clean checkout with root `bun.lock`, root `LICENSE`, root `CHANGELOG.md`, and all seven packages migrated to Bun, shared Biome/TypeScript config, Rolldown, and `bun test`.
- **When:** A contributor or CI runs `bun install --frozen-lockfile`, `bun run check`, `bun run typecheck`, `bun run build`, and `bun run test`, and loads packed tarballs of the five public plugins (and `pi-context-aco`) in Pi outside the checkout.
- **Then:** All checks, builds, and `bun test` suites pass; each plugin loads its built `dist/index.js` cleanly in Pi and ships `dist/CHANGELOG.md` referenced by `pi.changelogPath`; `pi-quota-keeper` resolves `proper-lockfile`; no tarball contains `vendor/*.tgz` or bundled host SDKs; and multi-plugin combinations interoperate over `pi.events` with isolated lifecycles.

### PR and `main` CI workflow blocks regressions
- **Given:** A pull request or push to `main` introduces a Biome violation, TypeScript error, Rolldown build failure, or failing `bun test`.
- **When:** `.github/workflows/ci.yml` runs.
- **Then:** The CI job fails visibly before merge and never attempts npm publication or Release creation.

### Stable tag release publishes public catalog, verifies `latest`, and creates GitHub Release
- **Given:** All five configured public packages have version `X.Y.Z` and valid `@monkeyman520/*` public metadata (including `pi.changelogPath: "./dist/CHANGELOG.md"` and `keywords: ["pi-package"]`), root `CHANGELOG.md` has a matching `X.Y.Z` heading, `pi-context-aco` and `pi-plugin-support` remain private and excluded, npm Trusted Publishing is configured externally, and all validations pass.
- **When:** A maintainer pushes matching tag `vX.Y.Z` to `Monkeyman520/pi-toolkit`.
- **Then:** `validate` builds, tests, packs, and verifies the five tarballs (including `dist/LICENSE` and `dist/CHANGELOG.md`); `publish` uploads all five packages to npm via OIDC with `--tag latest`, confirms both exact version `X.Y.Z` and `dist-tags.latest === X.Y.Z` on npm, and creates one stable GitHub Release for `vX.Y.Z` with `make_latest: "true"`, generated notes, and the five `.tgz` assets; private root, `pi-plugin-support`, and `pi-context-aco` are not published; no commit, changelog edit, or tag mutation occurs.

### Non-release inputs cannot publish
- **Given:** A branch push, unrelated tag, or prerelease tag (e.g., `v1.0.0-beta.1`).
- **When:** GitHub processes the push or `scripts/release.ts` evaluates the tag.
- **Then:** No npm publication or GitHub Release occurs.

### Version mismatch, missing changelog entry, or artifact defect blocks external changes
- **Given:** Tag `vX.Y.Z` disagrees with at least one configured public package version, OR root `CHANGELOG.md` lacks a Pi-compatible `X.Y.Z` heading, OR a quality check / tarball inspection fails (e.g., missing `dist/index.js`, mismatched `dist/LICENSE` or `dist/CHANGELOG.md`, unexpected file, or private flag on a configured public package).
- **When:** The release pipeline runs `validate` / `pack`.
- **Then:** Execution aborts with an identifiable error before any npm upload or GitHub Release API call.

### Missing npm OIDC trust or `latest` tag mismatch fails visibly
- **Given:** Validation passes, but npm Trusted Publishing is not configured / rejects authentication, OR after upload `dist-tags.latest` does not point to `X.Y.Z` within the visibility window.
- **When:** `publish` runs.
- **Then:** Publication fails visibly without falling back to a stored token and without creating/finalizing a successful GitHub Release.

### Idempotent retry completes partial npm or GitHub Release failure
- **Given:** A previous run for `vX.Y.Z` published some packages before failing on a later npm upload, OR published all npm packages before failing mid-way through GitHub Release draft/asset upload.
- **When:** The failed `publish` job is rerun for the same `vX.Y.Z` tag.
- **Then:** Already-published exact `name@version` packages are skipped (after verifying `dist-tags.latest === X.Y.Z`, while non-404 registry lookup errors still abort), missing packages are published, the existing draft/release is resumed, matching SHA-256 assets are kept, mismatched assets are replaced without duplicates, and the Release is finalized with `make_latest: "true"` once all assets exist.

### Configurable inclusion of `pi-context-aco`
- **Given:** `pi-context-aco` is excluded from the initial public release list and remains `private: true`.
- **When:** The release script loads packages for `vX.Y.Z`.
- **Then:** `pi-context-aco` is neither required to match `X.Y.Z` nor packed/published, while adding its directory to the single configured release list (together with public manifest metadata) enables it through the exact same validation/pack/publish pipeline.

## Decisions

- **Choice:** Private root Bun workspace, shared Biome & base TypeScript config, Rolldown ESM bundling (`dist/index.js`, `dist/LICENSE`, `dist/CHANGELOG.md`), inlined private `pi-plugin-support`, and full migration to `bun test`.
  **Reason/source:** Confirmed by user during refinement (`1a-A`, `1b-A`, `2c-A`, `2-A`) to align with `wangjq4214/pi-delegate` and Pi 1.5.2 changelog packaging; recorded in [ADR 0008](../adr/0008-bun-workspace-rolldown-and-bun-test-stack.md) (superseding ADR 0002 and partially superseding ADR 0005's archive distribution mechanism).
- **Choice:** `@monkeyman520/*` npm scope, `MIT` license, initial 5-package public catalog (configurable exclusion of `pi-context-aco`, permanent exclusion of `pi-plugin-support`), unified `vX.Y.Z` stable tags, npm Trusted Publishing (OIDC) with `--tag latest` + post-publish `dist-tags.latest === X.Y.Z` verification, shared root `CHANGELOG.md` for native Pi "Extension Updates", GitHub Release with `make_latest: "true"` and `.tgz` assets (idempotent retry, no movable Git `latest` tag), plus PR/`main` CI workflow.
  **Reason/source:** Confirmed by user during refinement (`2a`, `2b`, `2d`, `3a-A`, `3b-A`, `3c`, `1-A`, `2-A`, option `A`); verified against npm dist-tag protocol (npm forbids semver dist-tags such as `v0.1.0`) and Pi 1.5.2 `docs/packages.md` / `docs/cli.md`; recorded in [ADR 0009](../adr/0009-public-npm-trusted-publishing-and-stable-tag-releases.md).
- **Choice:** Preserve `packages/<plugin-name>/` independent package installation boundaries and externalize host peers + `proper-lockfile`.
  **Reason/source:** [ADR 0001](../adr/0001-independently-installable-pi-packages.md), [ADR 0008](../adr/0008-bun-workspace-rolldown-and-bun-test-stack.md), and verified runtime dependency in `packages/pi-quota-keeper/package.json`.

## Test Plan

- **Workspace & migration verification:** Install Bun in the development environment (not currently on PATH at refinement time), run `bun install --frozen-lockfile`, `bun run check`, `bun run typecheck`, `bun run build`, and `bun run test` across all seven packages and root tests.
- **Pi runtime & isolation verification:** Run per-package Pi smoke tests and cross-plugin isolation matrix against built `dist/index.js` and packed `.tgz` artifacts outside the repository checkout, confirming `pi-plugin-support` inlining preserves `pi.events` discovery and isolated plugin lifecycles, `pi-quota-keeper` loads `proper-lockfile`, and `dist/CHANGELOG.md` is present and matches `pi.changelogPath`.
- **Offline release pipeline unit/contract tests (`tests/release.test.ts`, `tests/workspace.test.ts`):** Verify tag parsing, manifest checks (`keywords`, `pi.changelogPath`), root `CHANGELOG.md` version-heading validation, configurable package exclusion (`pi-context-aco` / `pi-plugin-support`), real local `npm pack` + `tar` inspection including `dist/LICENSE` and `dist/CHANGELOG.md` (no publication), registry 404 vs. error handling, post-publish exact-version and `dist-tags.latest === X.Y.Z` polling/mismatch/timeout, partial npm retry skipping, GitHub Release draft/asset digest recovery and `make_latest: "true"`, and static assertions on `.github/workflows/release.yml` and `.github/workflows/ci.yml` (triggers, permissions, repo guard, no `NPM_TOKEN`, job ordering).
- **Evidence boundary:** Offline tests and local `pack`/`verify` prove script logic, archive integrity, and workflow structure; they do **not** prove external npm account ownership, npm Trusted Publishing OIDC configuration, or live GitHub Actions / live `pi update --extensions` registry execution. Actual npm trust setup and the first real `vX.Y.Z` release require separate maintainer authorization and execution.

## Out of Scope

- Prerelease channels (`alpha`/`beta`/`rc`) or independent per-package versioning / Changesets.
- Automatic version bumping, changelog editing, release commits, or tag creation by GitHub Actions.
- Custom in-extension runtime npm registry polling / update-banner network requests inside plugins (handled natively by Pi CLI `pi update` and `CHANGELOG.md`).
- Movable Git `latest` tags on GitHub or invalid semver npm dist-tags (such as `v0.1.0`).
- Publishing the workspace root, `pi-plugin-support`, or `pi-context-aco` in the initial release catalog.
- Configuring live npm Trusted Publishing records, creating initial npm packages, pushing release tags, or executing a real npm/GitHub release during implementation.
- Changing functional behavior of individual Pi plugins beyond build/entry packaging, `pi.changelogPath`, and `bun:test` migration.

## Future Evolution

- **Opting `pi-context-aco` into public releases:** Once ACO exits experimental maturity, maintainers can switch its manifest from `private: true` to public `@monkeyman520/pi-context-aco` metadata, configure its npm Trusted Publisher, and add `"pi-context-aco"` to the release catalog in `scripts/release.ts`.
- **Optional Git hooks (`lefthook.yml`):** May be added later if desired, following `pi-delegate`, without affecting CI or release workflows.
