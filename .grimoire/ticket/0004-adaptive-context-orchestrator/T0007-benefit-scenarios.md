### Important structural finding

Adaptive selected checkpoint→prune. The checkpoint **succeeded** in about 49.8 ms with scoped original UI/source/goal/plan segments, demonstrating real recoverable archival. The prune executor then refused the operation; `advance` correctly had nothing pending. No safety condition was relaxed.

The actual UI tool-call assistant contained **thinking + toolCall + an empty text block**. Current exact-prune removes complete legal tool exchanges and deliberately refuses paired assistants carrying additional reasoning or text (`extensions/prune.ts`, `evaluatePruneCandidates`). A read-only classifier check against the completed real branch returned exactly **“Paired assistant carries additional reasoning or text”** for the selected reference. Thus this was not the earlier 128-original limit, network failure, or lack of completed research. Source structure itself made the candidate unsupported.

The same branch counterfactual observer reported **zero removed bytes on every real adaptive request**. The native controlled provider's pure-tool-call case demonstrated 4,437 bytes/two messages removed, raw originals retained, and target absent from a subsequent actual provider request; the mixed reasoning shape did not qualify. These are separate evidence classes, not a successful real-model unload.

### What is—and is not—a measured benefit?

1. **Recoverable unloading works in the supported pure-tool-call shape:** completed, unreferenced UI lookup is absent from later requests while exact originals remain available. Its 4,437-byte contribution no longer repeats. That is a context-capacity benefit; the controlled zero-tariff fixture cannot establish money savings.
2. **Adaptive can identify a phase transition and preserve goal/plan:** this real run selected an expendable-lookup candidate, established a verified archive, and stopped when the deeper structure guard refused it. This is guarded coordination/recovery value, not released context capacity.
3. **For the current tested Gemini/high output shape, automatic exact unloading produced no benefit:** the necessary paired message is mixed with reasoning/text. A completed/redundant label alone cannot make it safe or executable.
4. **Near completion, no-op avoids an unnecessary intervention:** reuse the completed real P3 review/no-op evidence; context remains available, zero extra decision-model calls. It does not prove a causal speed or token improvement.

The observed 6.37M-versus-8.62M token difference and 19.40-versus-23.91 minute wall time are **not attributable to pruning**, because no pruning occurred. The models made different numbers of ordinary requests and UI rereads (one adaptive, two control), with uncontrolled sampling/cache/service state and serial ordering. Do not describe that difference as an ACO savings percentage. This single pair does not establish general quality, speed or cost superiority.

### Practical condition

Adaptive's context-capacity benefit can appear only when there is truly completed/disposable material, a bounded verified checkpoint, no protected dependency, legal supported exchange structure, and enough subsequent work to reuse the freed capacity. If the paired assistant carries reasoning/text—as in this configured model's observed output—the current exact-prune path refuses it. For this configuration, use observation/checkpoints for visibility/recovery; do not enable adaptive on the promise of automatic token savings. Supporting a safe narrower representation would be separate design/implementation work, not an unannounced benchmark workaround.
